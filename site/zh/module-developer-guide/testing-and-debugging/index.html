    测试与调试¶

    测试策略¶

    每个模块至少应在三个层面得到验证。

    单元测试¶

    验证参数处理、纯逻辑、边界条件和确定性输出。

    契约测试¶

    确认模块符合公开平台契约：

    • type 是否正确；
    • 元数据是否完整；
    • 输出结构是否符合约定；
    • 输入缺失时是否安全；
    • 正常执行时是否没有禁止的副作用。

    组合测试¶

    把模块放进一个真实的模块链里进行验证，上下游依赖可以由测试替身或轻量参考模块提供。

    推荐的 pytest 结构¶

    tests/
  test_params.py
  test_lifecycle.py
  test_outputs.py
  test_composition.py

    调试建议¶

    • 修改业务逻辑前先确认输入是否正确；
    • 先检查上游模块标识是否与配置引用一致；
    • 优先排查排序和运行模式假设；
    • 用最小可复现组合重现问题；
    • 输出结构一旦变化，文档和测试必须同步更新。

    故障排查表¶

    现象 常见原因 首先检查
    构造时失败 参数无效 结构校验和语义校验
    下游拿不到输出 模块 id 不对或未写入上下文 module_id 与输出映射
    组合被拒绝 顺序或类型缺失 校验规则
    不同模式行为不一致 隐含执行假设不兼容 运行模式说明

    日志建议¶

    优先在宿主应用中使用结构化日志。模块自身应暴露足够的诊断状态，但不应强绑定到某一种日志后端。

    发布门槛¶

    如果测试、示例和文档中的参数名、输出结构或兼容性描述不一致，该模块不应发布。
