# 模块类型

## 支持的模块类别

当前平台通过公开模块基类暴露以下模块类别。

| 类型 | 作用 | 常见输出 |
| --- | --- | --- |
| `indicator` | 从市场数据或上下文推导衍生值 | 数值或结构化指标结果 |
| `signal` | 生成交易意图或状态判断 | 信号状态、置信度、原因 |
| `filter` | 对信号进行筛选、抑制或限定 | 通过或阻断决策 |
| `risk` | 评估交易或仓位风险约束 | 风险结论或限制条件 |
| `sizer` | 决定暴露规模或数量 | 仓位大小建议 |
| `position` | 生成仓位层面的动作决策 | 开仓、平仓、持有、减仓 |
| `execution` | 将仓位意图转换为可执行动作 | 执行负载或动作请求 |
| `output` | 输出记录、报表或衍生结果 | 输出产物 |
| `portfolio` | 做组合级聚合或叠加处理 | 组合指标或组合指令 |

## 各类型开发建议

### 指标模块

应尽量保持纯计算和无副作用，为下游模块稳定提供可复用数值。

### 信号模块

建议输出结构化结果，而不是只返回布尔值，这有助于下游模块追踪来源和原因。

### 过滤模块

过滤模块要特别注意透明性，必须明确阻断条件以及在输入缺失时的行为。

### 风险模块

自定义风险模块可以表达策略局部约束，但不应试图复刻平台系统级风险内部能力。

### Sizer 与 Position 模块

数量决策和方向决策最好拆开，这样组合验证与测试都更容易。

### 执行模块

执行模块属于受控的高级扩展点，不应被视为普通第三方模块开发的默认路径。它应保持通用、参数驱动，并与基础设施秘密隔离。

### Output 与 Portfolio 模块

建议保持观测性或聚合性，不要引入让上游业务逻辑难以理解的隐藏控制流。

## 类型选择检查表

- 如果主要职责是计算值，大概率属于指标模块。
- 如果主要职责是给出交易意图，大概率属于信号或仓位模块。
- 如果主要职责是批准或否决动作，大概率属于过滤或风险模块。
- 如果主要职责是决定数量，它就是 sizer。
- 如果主要职责是把意图桥接为执行动作，它就是执行模块。
- 如果主要职责是记录或聚合，它更可能属于 output 或 portfolio 模块。
