# 校验与排序

## 为什么需要校验

平台在运行前验证模块组合的结构正确性，以便尽早、统一地发现配置错误，而不是把问题留到运行时才暴露。

## 标准执行顺序

批准的模块顺序如下：

1. `indicator`
2. `signal`
3. `filter`
4. `risk`
5. `position`
6. `execution`
7. `output`
8. `portfolio`

这个顺序反映了从数据推导、决策形成、风险约束、仓位决策、执行桥接到结果输出的依赖流向。

## 运行模式规则

### 面向实盘的组合

实盘组合至少满足：

- 至少一个指标模块；
- 至少一个信号模块；
- 至少一个仓位模块；
- 恰好一个执行模块；
- 执行模块必须位于所有仓位模块之后；
- 不允许顺序违规。

### 面向回测的组合

回测模式同样要求顺序合法。如果存在执行模块，它必须是平台批准的仿真型执行模块，而不能依赖真实执行基础设施。

## 准备层行为

在校验完成前，准备层可能会对模块进行顺序规范化，也可能在批准范围内补充默认执行模块。模块作者不应依赖这些默认行为，示例文档中应始终显式写出完整模块集合。

## 常见错误

- 把过滤模块放到信号模块之前；
- 假设仓位模块能先于指标计算运行；
- 在同一个组合里放多个执行模块；
- 实盘组合缺少仓位模块；
- 在回测示例中混入实盘专属执行假设。

## 发布前检查

- 模块类型声明是否和职责一致；
- 示例中的模块顺序是否标准；
- 上游依赖是否写清楚；
- 输入缺失时行为是否写明；
- 运行模式兼容性是否有明确声明。
