# 概览

## 范围说明

该平台采用组合式策略开发模式。一个策略由多个职责清晰、参数可校验、类型已声明的模块组合而成。

本套文档仅面向模块开发者，帮助你在公开边界内构建新模块，而不是解释平台专有的交易内部实现。

## 开发流程

模块开发遵循契约优先的路径：

1. 选择目标模块类型。
2. 按模块基类实现必要方法。
3. 声明元数据与参数模式。
4. 核对排序和组合约束。
5. 在隔离场景和组合场景中测试。
6. 随模块一起交付文档和示例。

## 建议心智模型

可以把平台理解为一个组合运行时，它会：

- 接收按顺序定义的模块列表；
- 在运行前做结构性校验；
- 根据批准顺序执行模块；
- 通过受控上下文共享数据与输出；
- 保存模块产出供下游模块消费。

至于内部编排、执行后端、系统级风控与基础设施服务，这些不属于模块作者需要依赖的知识范围。

## 公开事实来源

本门户当前依据平台稳定的公开契约与校验层进行抽象，包括：

- `ModuleBase`
- `ModuleRegistry`
- `StrategyValidator`
- `StrategyPreparer`
- `ModuleExecutionOrder`
- 平台级模块配置模型

## 非目标

本门户不解释以下内容：

- 下单路由和经纪商连接；
- 交易所或执行适配器内部行为；
- 平台核心风险算法；
- 生产基础设施与运维细节。

## 生产级模块的标准

一个可发布的模块至少应满足：

- 正确实现公开契约；
- 对参数进行结构和语义校验；
- 不依赖隐式外部环境；
- 在重复执行下具有可预测行为；
- 具备参数说明、输出说明、测试与故障说明。
