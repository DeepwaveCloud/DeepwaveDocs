# 贡献流程

## 治理目标

企业级文档是模块交付标准的一部分。一个模块如果没有与代码、示例、测试一致的文档，就不算完整交付。

## 必须一起提交的内容

每一个新模块贡献至少应包含：

- 实现代码；
- 测试；
- 参数参考；
- 一个使用示例；
- 故障说明；
- 如果引入新能力，还要完成边界评审。

## 文档评审标准

评审人应确认：

- 模块类型是否正确；
- 公开术语是否一致；
- 示例是否安全且不绑定环境；
- 是否泄露内部或专有细节；
- 如果项目要求双语，中英文页面是否保持等价。

## 变更控制

### 小变更

例如错别字、表述优化、非破坏性示例更新。

### 契约变更

例如参数改名、输出结构变化、生命周期预期变化、新增批准模块类型。

契约变更必须同步更新测试、示例以及两个语言版本的文档。

## 建议发布流程

1. 起草模块与参考文档；
2. 完成单元测试、契约测试和组合测试；
3. 完成公开边界审查；
4. 更新中英文文档；
5. 构建静态站点并检查链接；
6. 如果契约变化，对外附带发布说明。
