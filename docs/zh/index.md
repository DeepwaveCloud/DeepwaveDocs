# DeepWave 模块开发者文档

本门户提供面向外部与内部模块开发团队的正式文档集，用于指导开发可复用的策略模块，并确保开发过程遵循平台公开契约而不是依赖内部实现细节。

## 文档目标

本网站说明如何设计、实现、校验、测试和维护自定义模块，同时明确哪些内容属于平台内部能力，不能作为外部开发依赖。

## 适用对象

- 开发指标、信号、过滤、风险、仓位、执行等模块的工程师。
- 负责策略组合规范的架构师。
- 负责模块验收与兼容性验证的 QA 团队。
- 负责维护扩展文档模板和标准的技术写作者。

## 文档覆盖范围

- 模块基类所定义的公开契约。
- 组合式策略中支持的模块类型及职责边界。
- 模块校验规则、排序规则与运行模式兼容性。
- 配置模式、DSL 示例、测试要求与发布清单。

## 明确不公开的内容

- 平台内部执行编排与事件链路实现。
- 经纪商、交易适配器、执行后端的内部细节。
- 核心风险算法、阈值策略、基础设施秘密信息。
- 生产环境拓扑、凭据、真实接口地址。

!!! note "以公开契约为准"
    如果某个行为没有在本门户或单独批准的 API 契约中说明，就应视为内部实现，不应作为模块开发依赖。

## 文档结构

| 栏目 | 内容 |
| --- | --- |
| 快速开始 | 角色、边界与开发路径 |
| 架构说明 | 面向模块作者的安全架构视图 |
| 模块开发指南 | 契约、类型、校验、配置、示例 |
| 参考资料 | 公开边界与统一术语 |
| 文档治理 | 文档和模块标准如何演进 |

## 建议阅读顺序

1. 先阅读“快速开始”，理解本门户的边界与非目标。
2. 再阅读“公开架构”，建立正确的系统心智模型。
3. 在写代码前阅读“模块契约”和“模块类型”。
4. 使用“模板与示例”作为脚手架。
5. 提交前完成“测试与调试”中的检查项。

## 文档原则

- 使用显式契约，而不是依赖口口相传的经验；
- 优先给出可复现示例，而不是只有叙述；
- 示例必须保持通用且与环境无关；
- 只记录扩展点，不泄露核心实现秘密；
- 中英文页面在能力和约束上必须保持等价。
